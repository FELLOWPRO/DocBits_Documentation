# 采购订单匹配诊断

## 概述

许多发票会卡在采购订单这一步。发票上的内容与采购订单（PO）上的内容不一致，DocBits 无法自行判断它们是否匹配。每份这样的文档都需要人工处理，因此它**不是无接触式处理**。

Touchless Intelligence 会显示采购订单匹配失败的**原因**，以及 DocBits **如何**尝试匹配。本页介绍涉及的两个管道阶段、你会看到的失败原因，以及**采购订单匹配决策流程**图，该图按顺序展示匹配步骤。

### 在 Touchless Intelligence 中查看采购订单匹配的位置

| 位置                                                                                       | 你会看到的内容                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **无接触式处理率首次下降的位置**（概览选项卡）                                            | 一条柱状信息，例如 _PO line match: PO item mismatch_。它会告知有多少份文档卡在了此处                                                                                  |
| **供应商机会**                                                                  | 根本原因是**采购订单匹配**的供应商                                                                                                                                  |
| **供应商诊断**中的 **此组织的匹配方式**部分和**问题簇** | 此组织规则集的决策流程                                                                                                                        |
| **文档追踪**                                                                          | 状态为 **blocked** 且带有原因的 **PO Line Match** 阶段                                                                                                          |
| **设置 → 文档类型 → 更多设置 → 采购订单**                              | 匹配规则本身。请参阅[采购订单匹配规则](../../settings/global-settings/document-types/more-settings/purchase-order/purchase-order-matching-rules.md) |

## 两个采购订单阶段

| 阶段                  | 问题                                    | 停止原因                                                                                                            |
| ---------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **9 · 采购订单查找**      | 是否有与此发票对应的采购订单？ | _未找到采购订单_                                                                                            |
| **10 · 采购订单行匹配** | 每个发票行项目是否都与采购订单行项目匹配？    | _采购订单项目不匹配_、_采购订单行标识符不匹配_、_单价超出采购订单容差范围_、_数量超出采购订单容差范围_ |

在第 9 或第 10 阶段停止的文档，会在供应商队列中显示首个阻塞原因为**采购订单匹配**。

## 采购订单匹配失败的原因

| 你看到的原因                      | 含义                                                                                              | 典型原因                                                                                             | 要更改的内容                                                                                                                                                       |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **未找到采购订单**        | DocBits 未找到发票上采购订单编号对应的采购订单                                           | 采购订单编号读取错误或缺失；采购订单尚未导入；采购订单属于其他供应商 | 检查此供应商的采购订单编号提取、采购订单主数据导入以及供应商关联                                                                    |
| **采购订单项目不匹配**                | 发票行项目未能与采购订单行项目匹配                                                               | 供应商使用自己的项目编号；描述不同；行项目被合并或拆分               | 检查项目编号映射和匹配规则中的**规则优先级**；添加适用于该供应商行项目识别方式的规则                              |
| **采购订单行标识符不匹配**     | 发票上的行编号或标识符与采购订单不匹配                                         | 供应商重新编号了行项目                                                                              | 按项目和数量匹配，而不是按行编号匹配                                                                                                                 |
| **单价超出采购订单容差范围** | 价格差异超过了允许的容差                                                          | 实际价格变更、舍入差异或价格单位不同                                      | 检查规则集中的**单价容差**；更正采购订单或联系供应商                                                                               |
| **数量超出采购订单容差范围**   | 数量差异超过了允许的容差                                                       | 部分交付、超量交付                                                                           | 检查**匹配数量依据**和**数量容差**                                                                                                           |
| **采购订单匹配服务错误**       | 匹配服务未能响应                                                                      | 临时技术问题                                                                             | 重新处理文档；如果问题重复出现，请联系支持                                                                                                                 |
| **已禁用自动导出采购订单**    | **采购订单匹配 100% 时自动导出**设置已关闭，因此匹配的文档不会自动导出 | 设置已关闭                                                                                        | 如果需要自动导出，请启用此设置。请参阅[采购订单匹配 100% 时自动导出](../../settings/document-processing/module/auto-export-if-po-matched-100.md) |

{% hint style="info" %}
并非所有采购订单匹配原因都能在 DocBits 中解决。如果供应商发送了错误的采购订单编号，卡片会显示**仅需供应商操作**：供应商必须更正文档并重新发送。
{% endhint %}

## 采购订单匹配决策流程

决策流程展示了 DocBits 如何尝试将发票行项目与采购订单行项目匹配。流程包含**五个阶段**，第一个匹配成功的阶段即为最终结果：

1. **单项匹配验证**：按优先级顺序应用规则。这是常见情况，即一个发票行项目对应一个采购订单行项目
2. **多项匹配验证**：单项匹配后，当任一侧涉及多个行项目时使用
3. **总额匹配验证**：仅在完全没有匹配结果时使用。将采购订单行项目总额与其表格行项目之和进行比较
4. **单项不匹配验证**：忽略单价，因此即使价格不同，也可以按项目和数量匹配行项目
5. **回退逻辑**：剩下一个采购订单行项目和一个表格行项目时，将它们配对

在各阶段内部，DocBits 按以下顺序尝试：

* **所有规则精确匹配**：所有比较值完全相同
* **基于容差的匹配**：数值可以在容差范围内偏差
* **包装条件**：最后一次匹配尝试，依据规则集中的包装相关条件

每一步都会询问**是否找到匹配项？**回答**是**（绿色）会进入**已找到匹配项**，文档继续处理。回答**未匹配**（红色）会进入下一步；最后一步之后，结果为**未找到匹配项**：文档停止处理并需要人工处理。

### 流程图标题栏的内容

| 字段                                             | 含义                                                                                                |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **文档类型**                                 | 规则集所属的文档类型，例如 INVOICE                                         |
| **规则集版本**                              | 匹配规则的版本，例如 v3                                                      |
| **规则集所有者**                                | **此组织**（你自己的规则）或 **随附的默认规则集**（DocBits 的标准规则） |
| **已发布**                                     | 版本的发布日期                                                                         |
| **匹配数量依据**                             | 要比较的数量类型（订购数量、未结数量）                                           |
| **容差金额**                              | 容差来自文档类型属性还是规则集                     |
| **单价容差** / **数量容差** | 价格或数量允许的偏差幅度                                                             |
| **默认容差**                             | 所有其他数值的容差                                                             |

在上面的示例中，容差显示为**未配置**和**未生效：由属性决定**。这表示规则集本身没有自己的容差，并且**容差金额**一栏说明容差来自**文档类型属性**。只有在生效时，容差才会影响判断。价格或数量差异导致文档受阻时，请先查看这一栏：它会告诉你应该**在哪里**更改容差。

规则集状态会以备注形式显示：**活动版本**（由这些规则决定）、**已批准，未激活**、**草稿，尚未生效**或**版本状态未知**。只有活动版本会影响判断。

如果转换规则在匹配前更改了文档，流程图会显示相应信息，例如 _已应用 2 项：（名称）_ 或 _“（规则）”重建了（表格）：采购订单匹配在此处丢失_。这是一个经常被忽略的原因：重建表格的规则可能会破坏原本有效的匹配。

## 示例

以下示例中的数字仅用于说明。

### 示例 1：价格在容差范围内

某发票行项目的单价为 **10.40**。采购订单行项目的单价为 **10.00**。单价容差为 **5 %**。

* **精确匹配**失败（10.40 不等于 10.00）。
* **基于容差的匹配**成功：差异为 **4 %**，在 5 % 的容差范围内。
* 行项目匹配成功。**已找到匹配项。**

如果容差为 **3 %**，基于容差的匹配也会失败。所有阶段结束后，文档会因**单价超出采购订单容差范围**而停止。流程图会准确显示这一流程；解决方法是调整容差（如果 4 % 的偏差在你的业务中可以接受），或要求供应商更正。

### 示例 2：供应商使用的项目编号与你的不同

供应商开具的发票上，项目编号为 **"A-4711-X"**；你的采购订单上则为 **"4711"**。没有规则对这两个编号进行比较，因此找不到匹配项。Touchless Intelligence 会将该供应商的所有发票归入同一个问题簇：**采购订单行匹配，采购订单项目不匹配**，共 27 份文档。

* 在问题簇中，你会看到 _27 份受影响，27 份可恢复_，预期提升例如为 **+8.7 pp**。
* 解决方法在你这边：添加或调整规则顺序，使其按供应商项目编号或描述进行匹配；也可以在主数据中维护供应商项目编号。
* 更改规则后，通过[更改提案](touchless-change-proposals.md)应用更改，并在两周后查看**更改历史记录**：对比前后纯匹配率。

### 示例 3：采购订单尚不存在

发票在采购订单导入之前到达。它们会在**采购订单查找**阶段因**未找到采购订单**而停止。问题簇会显示一个短暂峰值。解决方法是调整流程顺序或采购订单导入计划，而不是修改匹配规则。检查**无接触式处理率首次下降的位置**：如果每次导入间隔后，_PO lookup: Purchase order not found_ 柱状信息都会上升，就说明可能是这个原因。

### 示例 4：某条规则重建了表格

针对某供应商表格的转换规则生效后，该供应商的匹配率急剧下降。受影响文档的流程图显示 _“（规则）”重建了（表格）：采购订单匹配在此处丢失_。解决方法是调整或撤销转换规则，而不是修改匹配规则。

## 处理采购订单匹配问题的常规步骤

1. 打开**无接触式处理率首次下降的位置**。某个采购订单匹配阶段是否排在前三位？
2. 打开**供应商机会**并按**预期提升**排序。选择根本原因是**采购订单匹配**且状态为 **RECOVERABLE** 的供应商。
3. 打开**供应商诊断**并查看问题簇：原因、受影响的文档、**要更改的内容**、**缺少的证据**。
4. 打开**此组织的匹配方式**并检查规则集：版本、所有者和容差。
5. 打开一份**示例文档**及其[文档追踪](touchless-document-trace.md)：它卡在哪个阶段，原因是什么？
6. 通过预览只更改**一**项内容（规则顺序、容差或项目映射），以便**更改历史记录**能够衡量效果。
