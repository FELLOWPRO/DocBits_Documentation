# 在 DocBits 中映射 XRechnung

在 DocBits 中，XRechnung 发票会根据预定义配置映射到特定字段，以确保数据能够顺利导出为各种格式，包括与 **Infor** 等其他系统集成。导出配置利用模板和规则，确保捕获 XRechnung 的每个元素并将其正确映射。

### 关键组件&#x20;

  1.  **文档类型**：XRechnung 文档会映射到 DocBits 中特定的 **文档类型**。每种文档类型（例如发票、贷项通知单、借项通知单）都有自己的结构和字段。

  2.  **字段映射**：XRechnung 中的字段通过 **导出配置文件** 映射到 DocBits 中对应的字段。此文件定义如何处理每个 XRechnung 字段，以及应将其导出到何处。

  3.  **导出规则**：系统会定义一些规则，以处理值可能不同的特定情况，包括容差检查、审批要求或行级费用。这些规则可确保根据特定业务逻辑正确处理并导出 XRechnung 数据。

### 从 `TypeCode` 动态生成 `invoice_type`

`invoice_type` 并非通过普通 XPath 查找提取。默认的 TRANSFORMATION XSLT 会就地覆盖源 `TypeCode` 元素，将 UN/CEFACT 1001 数字代码替换为易于理解的标签：

| 源 `TypeCode` | UNCL 1001 含义 | DocBits `invoice_type` |
|---|---|---|
| `381` | 贷项通知单 | **Credit Note** |
| `261` | 自开贷项通知单 | **Credit Note** |
| `380`, `383`, `384`, `386`, `389`, `325`, 任何其他值 | 发票 / 借项通知单 / 形式发票等 | **Invoice** |

替换发生在以下位置：

- **CII 变体**：`<ram:ExchangedDocument><ram:TypeCode>`
- **UBL 变体**：`<cbc:InvoiceTypeCode>`（发票配置文件）或 `<cbc:CreditNoteTypeCode>`（贷项通知单配置文件）

XRechnung 不会输出 `invoice_sub_type` — TRA 会保留源结构，而不是生成规范的 `<INVOICE>` 树。有关子类型行为，请参阅 FACTURX / ZUGFeRD 映射文档。
