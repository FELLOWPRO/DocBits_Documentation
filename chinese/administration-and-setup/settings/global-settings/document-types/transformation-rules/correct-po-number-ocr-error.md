# 纠正采购订单号中的OCR错误

`06O123`的第三个字符是**字母O**。如果提取结果为`060123`，可以使用带条件的前缀转换来纠正这一已知模式，无需编写自定义脚本。

## 配置前缀纠正规则

1. 打开**设置 → 文档类型 → 齿轮图标 → 转换规则 → 管理转换规则**。组织管理员必须先为所选文档类型启用此功能。
2. 新建**表头字段**规则，将**采购订单号（`Purchase Order`）**设为目标。输入来源选择**字段本身**。
3. 选择按条件执行，将条件设为采购订单号**开头为**`060`。
4. 删除初始的去除空格步骤。添加**词缀 → 移除前缀 → `060`**，然后添加**词缀 → 增加前缀 → `06O`**。第二步请输入大写字母O。条件将这两个步骤限制在受影响的前缀范围内，其余字符保持不变。
5. 检查实时预览，保存规则并重新打开。测试一个文档，保存后重新加载，以确认采购订单号已持久保存。

## 检查结果

| 示例输入 | 预期结果 | 原因 |
| --- | --- | --- |
| `060123` | `06O123` | 受影响的前缀 |
| `060987` | `06O987` | 另一个受影响的值；后缀保留 |
| `06O123` | `06O123` | 已经正确；条件不匹配 |
| `160123` | `160123` | 不同的前缀；条件不匹配 |
| `1060123` | `1060123` | 出现在值中间的`060`不是匹配的前缀 |

本例用于纠正已知的提取模式，不能证明OCR准确率、采购订单是否存在或订单匹配是否成功。仅当编号约定要求`06O`时才使用该规则：合法的`060`前缀也会被修改。如果该编号约定仅适用于部分供应商，请添加供应商条件。

## 为什么使用两个词缀步骤？

对于**查找并替换**等依赖位置的步骤，当前编辑器要求使用单独的源字段，即使启用了**每个文档仅执行一次**。上述两个前缀步骤可以作用于同一个字段。纠正后，值不再以`060`开头，因此后续保存时条件不匹配，规则会跳过该值。
