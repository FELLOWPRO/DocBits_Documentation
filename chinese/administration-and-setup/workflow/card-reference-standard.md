# 理解并配置工作流卡片

根据操作目的与数据范围选择卡片。**Field is** 检查字段存在性或空状态；**Docfield is** 比较字段值。分配文档、创建任务、发送通知是不同效果。类别名称不能替代某个具体卡片版本的说明。

## 完整卡片参考应说明什么

| 内容 | 必须回答的问题 |
| --- | --- |
| 身份 | 界面名称、技术类型、版本与 When/And/Then 角色是什么？ |
| 前提 | 需要什么授权、权限与文档数据？ |
| 输入 | 各参数的类型、值、默认值和允许选项是什么？ |
| 范围 | 读取字段、单行、全部明细还是组织级变量？ |
| 结果 | 成功、条件为假、错误各代表什么？下一张卡片能使用什么数据？ |
| 副作用 | 是否修改文档、任务或外部系统？测试会模拟哪些操作？ |
| 示例 | 哪些完整配置和输入会产生什么结果？ |
| 限制与版本 | 缺失数据、精确边界和旧版本会怎样？ |

## 完整示例：Docfield is

**技术类型：** `condition_docfield_operator_value` · **版本：** 2 · **角色：** And。需要定义了布局和待检查字段的文档。

| 输入 | 示例配置 |
| --- | --- |
| Field Name | `total_amount`，使用技术键名，不使用翻译后的标签 |
| Operator | `gt` / 大于 |
| Field Value | `1000`，不带货币符号 |

卡片读取当前文档字段并与配置值比较。它不会修改状态、创建任务或导出。Advanced 中，真走 Success，正常的假走 Failed Condition，求值错误走 Error。Standard 中，未满足的条件会停止线性序列。

实际验证的案例：**1785** → Success；**999** 和 **1000** → Failed Condition；**1000.01** → Success；金额缺失或数值无效 → Error。JSON 使用小数点。这些结果仅描述所示数字配置，不代表所有数据类型与运算符。

应将此卡片与明确提供容差的卡片区分。不要仅根据 `gt` 的行为推断相等或包含边界的比较；请对所需组合单独测试边界案例。
