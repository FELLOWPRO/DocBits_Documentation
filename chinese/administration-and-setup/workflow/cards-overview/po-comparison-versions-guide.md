# PO 比较：方向、公差和卡版本

PO 比较卡将所选面与参考面进行比较。该参考确定百分比公差的基础。首先完成采购订单匹配，然后选择特定卡要求的比较、运算符、任意/全部和容差。

## 比较方向

| 已存储选项 | 比较面 | 参考面 |
| --- | --- | --- |
| `po_document` | 采购订单 | 文件 |
| `received_document` | 收到数据 | 文件 |
| `po_received` | 采购订单 | 收到数据 |
| `document_po` | 文件 | 采购订单 |
| `document_received` | 文件 | 收到数据 |
| `received_po` | 收到数据 | 采购订单 |

接收方源自匹配的采购订单数据。单价卡上收到的比较可以使用数量来得出可比较的金额；它不是数量与货币价格的直接比较。检查计算时，请使用该卡在日志中记录的值。

## 为什么方向很重要

对于`100` 参考值和`110` 比较值，`5` 的百分比公差对应于参考值周围的`5`。如果文档是参考且其值可编辑，则更改文档也会更改公差基准。谨慎选择参考，尤其是自动批准时。

反转两边会反转排序运算符：`>` 变为`<`，`>=` 变为`<=`，反之亦然。相等和不相等比较的含义保持不变。在未检查所选侧面的情况下，请勿反转运算符。

包含比较迁移的版本将受影响的已保存卡片从`po_document`移动到`document_po`，从`received_document`移动到`document_received`，同时反转排序运算符。受影响的版本是数量容差 v4、订单确认到 PO v4 和单价 v4/v5。数量差异的组合价格不包括在保存卡迁移中。检查保存的配置并在发布后测试其业务成果；请勿再次手动反转。

## 单价卡版本

| 版本 | 配置 |
| --- | --- |
| v3 | 使用早期的比较行为。不要假设它公开了更新的方向和公差字段。 |
| v4 | 添加比较侧选择。 |
| v5 | 包括任意/全部、运算符、公差量、公差类型和比较侧选择。 |

选择固定金额的绝对容差和相对于所选参考的方差的百分比容差。使用该卡提供的运营商；完全平等和在公差范围内是不同的决定。不存在适合每个供应商或文档类型的通用业务容差。

## 验证示例

1. 使用匹配的采购订单参考`100` 和文档值`110`。
2. 选择文档与采购订单、提供的公差范围内比较以及`5` 百分比。期待带外比较。
3. 测试精确的容差边界、两侧的值以及缺失的匹配 PO。
4. 使用多条线，使用一条通过线和一条失败线来验证“任何”与“全部”。
5. 检查日志的比较值、选定的边、运算符和容差，然后验证生成的工作流分支。

不匹配的 PO、非数字值和错误的业务条件是不同的结果。不要将缺失数据视为成功匹配。对于费用，请使用 [Any / All Charges](and/compare-with-purchase-order/any-all-charges.md)，它分别解释了缺失费用行为和 v2/v3。
