## 选择支票

| 卡型 | 检查和配置 |
| --- | --- |
| `CONDITION_QUOTES_ITEM_NUMBER_COMPARISON` | 根据商品价格数据检查商品标识符。选择卡提供的比较和任意/全部字段。 |
| `CONDITION_SPECIFY_SUPPLIER_TYPE` | 将报价数据中的供应商类型与`supplier_type`进行比较。这是供应商分类检查，而不是价格比较。 |
| `CONDITION_QUOTE_SUPPLIER_ITEM_NUMBER_EXISTS` | 检查供应商商品 ID 是否出现在商品价格数据中；选择运算符和任意/全部。必须在日志中调查丢失的报价或项目数据。 |
| `CONDITION_QUOTE_PRICE_MATCH` | 将单价与所选供应商价格进行比较：`ManagedPrice` 或 `LastPrice`。选择任意/全部和数字比较运算符。两侧没有可比数字的行将被跳过并记录；如果没有可比较的行，该卡将报告丢失的文档数据。 |
| `CONDIITON_UNIT_OF_MEASURE_EQUAL` | 根据相关数据检查计量单位。技术类型包含保留的拼写错误；不要在存储的工作流 JSON 中更改它。不同单位表示的价格需要单独注意。 |
| `CONDITION_ITEM_QUOTES_TO_CONTRACTED_PRICE` | 比较报价和合同价格。版本 3 添加了任意/全部；见下文。 |

可见标签可能因版本和 UI 语言而异。通过实际检查来选择，而不是仅通过类别名称来选择。例如，“报价项目价格”可能出现在“逻辑”下，而其他报价检查则出现在“与报价比较”中。

## 报价项目价格：版本 3

选择相等或不等运算符，以及任何比较行或每个比较行是否必须满足它：

- `match_any`：一条成功的可比线就足够了。
- `match_all`：每条比较行必须满足所选运算符。

版本 2 保留了“全部”行为。 v3 上未设置的“任意/全部”设置会回退到“全部”并被记录。没有可比行的卡会报告丢失的数据；没有价格并不能证明平等或不平等。检查日志中跳过的行及其缺失的部分。

例如，两条可比较的线产生相等的结果 true 和 false。任何通行证；一切都失败了。对于不等式，每行的比较结果首先发生变化，然后“任意/全部”组合这些结果。它不会反转最终的 All 结果来实现 Any。

## 测试用例

使用准确的商品和供应商 ID、预期价格来源和匹配单位。测试所有行是否匹配、结果混合、没有可比价格、缺少报价数据以及错误的供应商 ID。验证比较结果以及跳过了哪些行。将批准或导出保留在实际需要的业务检查之后；成功的标识符检查并不是完整的采购验证。

请参阅[PO 匹配](po-matching-complete-guide.md) 进行采购订单比较，并参阅[工作流程日志](../workflow-logs.md) 进行故障排除]。

### 商品编号比较示例

**配置：**准备两个可比较的报价行：供应商项目`DEMO-S1`两侧映射到项目`DEMO-I1`；供应商项目`DEMO-S2`具有文档项目`DEMO-I2`和矩阵项目`DEMO-I9`。 Choose equality and `match_all`.

**预期结果及反例：** `match_all` 的条件结果为假，因为一个可比较的项目编号不同。 `match_any` 的结果为真，因为第一个项目编号匹配。查找使用供应商物料编号。没有项目编号的矩阵条目将被跳过并记录；如果没有可比较的行，则条件结果为 false。日期范围日志本身并不是单独的有效性条件。

这是一个说明性的测试配置和预期结果；它没有被执行。使用测试组织中配置的数据和收件人。

### 供应商项目存在示例

**配置：** 该文档有供应商项目编号`DEMO-S1`和`DEMO-S2`；加载的供应商商品价格数据仅包含`DEMO-S1`。 Choose the presence operator and `match_all`.

**预期结果及反例：** `match_all`条件结果为假，`match_any`条件结果为真。对于缺席运算符，第二行是正缺席结果。存在并不能证明项目价格、单位或供应商分类是正确的。首先加载有效的报价数据并检查缺失数据错误。

### 供应商价格示例

**配置：** 对于两条匹配线，选择`ManagedPrice`、相等和`match_all`。 Document prices are `10` and `12`;相应的管理价格为`10`和`13`，货币和单位相匹配。

**预期结果及反例：** `match_all`条件结果为假，`match_any`条件结果为真。切换到`LastPrice`使用不同的源，必须独立测试。没有可比数字价格的行将被跳过并记录；如果没有可比较的行，该卡将报告丢失的文档数据，而不是相等。

这是一个说明性的测试配置和预期结果；它没有被执行。使用测试组织中配置的数据和收件人。

### 供应商分类示例

**配置：**选择供应商类型`Contract`。准备两个加载的报价供应商条目，其中`managed_class`等于`contract`。

**预期结果和反例：**当每个加载的条目都具有该分类时，条件为真。如果一个条目具有分类 `managed`，则条件为假。可选的`Nonmanaged`值由后端标准化为`unmanaged`。此分类与供应商法律形式无关。缺少报价数据不匹配。

这是一个说明性的测试配置和预期结果；它没有被执行。使用测试组织中配置的数据和收件人。

### 计量单位示例

**配置：** 准备已匹配的报价行：单据单位为 `EA`，供应商比较单位也为 `EA`。选择相等比较和 `match_all`，并保持待测试的卡片版本。

**预期结果及反例：**匹配可比单位条件成立；使用 `KG` 而不是 `EA` 的第二个可比行使`match_all` 的条件为假。缺失的比较单元将被跳过并记录；如果没有可比较的，该卡会报告丢失的数据。版本 3 可能会应用配置的单元映射，因此请单独验证该映射。仅匹配价格并不能建立匹配单位。

这是一个说明性的测试配置和预期结果；它没有被执行。使用测试组织中配置的数据和收件人。
