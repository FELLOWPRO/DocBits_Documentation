## 用途：

**“Send HTTPS Request”（发送 HTTPS 请求）**工作流卡片支持用户向指定 URL 发送 HTTPS 请求，并自定义请求标头、参数和数据载荷。此卡片适用于在工作流中直接集成外部 API 或 Web 服务。

## 卡片组件：

1. **网址**
   * **说明：**指定 HTTPS 请求的发送目标端点。
   * **详细信息：**输入要连接的 API 或 Web 服务的完整 URL。
2. **Headers（请求标头）**
   * **说明：**定义 HTTPS 请求中要包含的请求标头。
   * **详细信息：**使用**有效的 JSON 格式**提供**键值对**，以指定身份验证令牌或内容类型等请求标头。例如：{"Authorization": "Bearer example\_value"}
3. **Method（方法）**
   * **说明：**指定请求要使用的 HTTP 方法。
   * **选项：**
     * **GET：**从端点获取数据。
     * **POST：**向端点发送数据，以创建或更新资源。
     * **PUT：**更新端点上的现有资源。
     * **DELETE：**从端点删除资源。
4. **Parameters（参数）**
   * **说明：**要作为查询参数包含在 URL 中的键值对。
   * **详细信息：**使用此项发送端点所需的筛选条件或其他数据，并采用有效的 JSON 格式。请参阅 Headers 的示例。
5. **Data（数据）**
   * **说明：**HTTPS 请求的正文。
   * **详细信息：**使用有效的 JSON 格式提供载荷。请参阅 Headers 的示例。

## 功能：

* **条件评估：**只有当 **“当”** 和 **“且”** 的条件评估结果为 true 时，卡片才会发送 HTTPS 请求。
  * 如果任一条件为 false，则不会发送请求。
* **请求执行：**
  * 条件满足时，系统会根据指定配置发送 HTTPS 请求。

## 设置和配置：

1. **定义 URL：**输入 HTTPS 请求的发送目标端点。
2. **设置请求标头：**以键值对形式提供所需的请求标头。
3. **选择 HTTP 方法：**根据要执行的操作，选择合适的方法（**GET**、**POST**、**PUT** 或 **DELETE**）。
4. **添加参数：**指定端点所需的查询参数。
5. **提供数据载荷：**如有需要，按要求的格式（例如 JSON）输入请求正文。
6. **配置条件：**定义 **“当”** 和 **“且”**，确保仅在满足特定条件时发送请求。

## 总结：

**“Send HTTPS Request”（发送 HTTPS 请求）**工作流卡片可让用户直接从工作流向外部服务发送自定义请求，从而简化 API 集成。通过自动发送 HTTPS 请求并管理响应，此卡片增强了工作流的灵活性和功能。
