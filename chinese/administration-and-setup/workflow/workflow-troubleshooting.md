# 系统诊断工作流问题

先锁定一次受影响的执行，记录组织与环境、工作流名称和已保存版本、文档引用、时间与时区、节点的确切消息。测试响应中还可以使用 `execution_id`。共享证据中不得包含访问密钥或未保护的客户数据。

## 从症状到检查

| 症状 | 查找证据 | 修正与复测 |
| --- | --- | --- |
| 没有执行记录 | 授权、模块、启用状态、时间筛选和匹配事件 | 修正入口与筛选，再次触发真实事件。手动 Start 不能证明该事件。 |
| 操作一直为灰色 | 前置节点结果和连接的出口 | 沿实际路径排查。被跳过的节点本身并没有执行失败。 |
| 条件为橙色 | 实际读取的字段键、类型、值和运算符 | 区分否定结果与求值错误；测试低于、等于和高于边界的情况。 |
| 节点为红色 | 首条错误消息与必需输入 | 修正数据或配置；复测错误案例与成功案例。 |
| Wait ALL 后没有操作 | 每个源节点及其连接的结果出口 | 不要同时要求互斥路径；为每个必需源证明存在可满足的路径。 |
| 任务或导出重复 | 多次执行、事件、状态变更和 Run Workflow 调用 | 限制触发条件和状态转换，同一案例测试两次。检查目标业务流程是否具备合适的并发保护。 |
| 变量影响其他工作流 | 组织级共享变量 | 检查依赖关系。变量独立于画布保存；对受影响工作流重新测试。 |
| 测试通过但没有实际效果 | 到底比较了什么、模拟了什么？ | 在文档中查分配、任务区域查任务、目标系统查接收。仅有预期状态不够。 |
| 导出已启动但接收方没有数据 | 导出历史、响应和接收端数据 | 重试前先定位问题，检查接收方是否已经处理了第一次请求。 |

## 正确理解消息

[高级案例](advanced-workflow-case-study.md)中，金额缺失会沿红色路径进入数据修正。错误处理和 OR 可以成功，而整体仍保留最初的错误。普通的金额条件为假时走橙色路径，标准分支仍可成功完成。

同一源节点的两条连线不是两次独立审批。汇合节点检查源节点实际采用的已连接结果。请检查完整流程；从中间节点开始的局部测试可能遗漏必需前置节点。

## 证明修正有效

1. 保留原始问题证据与业务预期。
2. 有针对性地修改数据或配置。只有业务要求改变时才修改预期。
3. 使用[练习包](workflow-training-kit.md)复测错误、成功及受影响边界案例。
4. 保存修正规则，并单独检查启用状态。
5. 对比新的真实执行与旧记录。旧日志始终描述当时的版本。

最后记录原因、修正措施、已证明的结果及剩余限制。区分等待时间和执行时间；总耗时较长本身并不能证明某个节点缓慢。

## 明确范围后重复单卡测试

在所检查的 Dev 设计器中，从选定节点测试后再重复测试，会切换到整个图。请重新打开目标卡片的右键菜单测试，并核对实际访问的节点。包含六个节点的结果不能证明只测试了一张空值检查卡片。失败操作计数也可能包含条件不满足的情况；还应查看所选出口、日志及整体结果。
