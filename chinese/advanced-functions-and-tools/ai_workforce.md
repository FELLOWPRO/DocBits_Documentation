# AI 工作团队

<figure><img src="../.gitbook/assets/docnet-agents-infographic-en.png" alt="AI 工作团队智能体信息图"><figcaption><p>DocBits 多智能体系统，用于自主处理文档</p></figcaption></figure>

## 概览

**AI 工作团队**是 DocBits 内部的编排层，可将收到的工作转化为由多个 AI 智能体协同处理的任务。无需人工逐步处理，它会接收一项输入工作——电子邮件、Microsoft Teams 或 Discord 中的聊天消息、UI 中的手动操作，或 API 调用——并推动其直至完成：对文档进行分类、提取并验证字段、与采购订单和主数据匹配，然后导出到 ERP；在需要的环节由人工参与。

可以把它看作由你管理的一支团队，而不是一个由你操作的工具。每项工作都会按照相同的固定结构流转：

* **编排器**接收一项**任务**（一个工作单元），制定计划并进行委派。
* 计划会拆分为多个**问题**（单项任务），分别交由**专业智能体**或**人工**处理。
* 专业智能体报告处理结果，编排器汇总最终结果。

承担这些角色的_智能体_并非固定不变：DocBits 提供可直接使用的 **DocBits 编排器**和两个默认专业智能体，你也可以创建自己的智能体（请参阅[智能体](ai_workforce.md#agents)）。

典型的端到端流程如下：一张发票通过电子邮件到达 → 创建一项任务 → 编排器制定计划，并向专业智能体分派问题（分类、提取、验证、采购订单匹配） → 敏感步骤暂停，等待人工在**收件箱**中审批 → 审批后，文档导出，任务完成。你可以在**仪表板**中查看整个流程，在**项目**中归集相关运行，并在需要人工决策时通过**收件箱**和**问题**介入。

## 如何启用

可在主设置中按组织启用 AI 工作团队。

1. 前往**设置 → 模块**。
2. 打开 **AI 工作团队**模块。
3. 在弹出的对话框中确认订阅。

启用后，主导航侧边栏中会显示 **AI 工作团队**，你的组织也可以开始使用此工作区。

## 仪表板

**仪表板**是 AI 工作团队的概览页面，可一目了然地查看 KPI、图表和活动列表。你可以选择要显示的指标。

若要配置当前显示的指标，请打开**设置**（齿轮图标），然后使用**仪表板小组件**面板。切换各个小组件的开关，然后点击**保存**；你的选择会作为个人偏好保存，因此每位用户都可以自定义自己的视图。

可用小组件包括：

* **团队监控** — 所有智能体的实时状态。
* **KPI 卡片** — 未解决问题、活动中的任务、已启用智能体、今日运行次数、令牌用量和待审批项。
* **图表** — 问题趋势、按状态统计的任务、电子邮件接收量、按优先级统计的问题、每日运行次数，以及按智能体统计的令牌用量。
* **列表** — 活动中的任务、近期活动、待审批项、分配给你的未解决问题、正在工作的智能体和受阻项目。

## 收件箱 <a id="inbox"></a>

**收件箱**用于处理需要**人工关注**的工作。当智能体即将运行需要签核的工具时，它会暂停任务，并在此处提交**审批请求**。这就是人在回路中（HITL）：只有人工做出决定后，操作才会执行。某个工具是否需要签核，由智能体的**审批模式**及其工具的 **critical** 标记决定（请参阅[智能体设置](ai_workforce.md#agent-settings)）。

每个收件箱项目都会显示请求标题、发起请求的智能体，以及需要做出决定的事项简述。你可以对项目执行以下操作：

* **批准** — 允许智能体继续执行操作。
* **拒绝** — 停止该操作。
* **评论 / 发送消息** — 在智能体继续之前向其提供其他指示。
* **打开任务** — 跳转到该项目所属的任务，查看完整上下文。

项目在有人处理前会保持**待处理**状态，之后变为**已解决**（如果项目被搁置而未作决定，例如其所属任务已取消，则变为**已忽略**）。收件箱导航项会显示待审批数量徽标，确保不会遗漏关键事项。

## 任务

**任务**是顶层工作单元，也是针对单一目标运行的智能体任务。每项任务可以包含多个工作步骤，并由**编排器智能体**协调；编排器负责规划工作、将工作拆分为问题并委派给专业智能体、跟踪处理结果并汇总最终结果。

任务会根据其**来源**创建——电子邮件、聊天（Microsoft Teams 或 Discord）、任务控制（手动）或 API——并在整个生命周期中保留相关上下文。你可以在**任务控制**中用自然语言描述想要完成的工作，亲自启动一项任务；之后由编排器接手处理。

任务会经历以下状态：

| 状态                    | 含义                                                           |
| ------------------------- | ----------------------------------------------------------------- |
| **规划中**              | 编排器正在分析请求并制定计划。    |
| **处理中** _(活动中)_ | 专业智能体正在执行计划中的问题。               |
| **等待审批**      | 任务已暂停，等待人工在收件箱中做出决定。 |
| **已完成**             | 所有问题均已处理完毕，任务目标已达成。         |

任务也可以**暂停**或**取消**。在任务详情视图中，你可以跟踪其**进度**、查看关联的**问题**、查看时间和令牌用量、打开事件**时间线**，以及**重新启动**、**编辑**或**删除**任务。

## 问题

**问题**是为完成任务目标的一部分而创建的单项任务，例如_导入文档_、_向发件人发送回复_或_手动审批某个步骤_。**专业智能体**和**人工**可以共同处理同一项任务。

每个问题都包含指派对象所需的上下文，并按照自身的生命周期流转（待办 / 处理中 → 审核中 → 已完成，或出错 / 已取消）。问题可以指派给智能体或人员、设置优先级（紧急、高、中、低）、关联到任务，并通过评论进行讨论。

你可以查看所有问题，按状态、优先级、指派对象或任务筛选，按状态、优先级或指派对象分组，也可以查看**我的问题**（指派给你的任务）。手动创建问题后，你可以直接在任务中为智能体或同事添加工作。

## 项目

**项目**是用于归集相关**任务**的文件夹，例如_第一季度某个供应商的所有发票_，然后再为_第二季度_创建另一个项目，依此类推。项目便于整理和查找大量智能体执行记录。

创建项目时，需要为其设置：

* **名称** — 例如 _"Acme 发票 Q1"_；
* 可选的**描述** — 说明项目内容以及预期结果；
* 可选的**截止日期** — 项目应保持活动状态至该日期。

项目的状态为**活动中**或**已完成**。如果项目设置了截止日期，**则会一直保持活动状态，直到该日期到达**，之后自动完成——因此，季度项目会在季度末自动关闭（每天检查一次）。未设置截止日期的项目会一直保持活动状态，直到你手动将其完成。你也可以随时手动完成项目或重新打开项目。在项目中，你可以查看其中包含的任务数量，并将更多任务关联到该项目。

## 智能体 <a id="agents"></a>

智能体是工作执行者。每个智能体都有一个**角色**，决定其在“编排器 → 任务 → 问题”流程中的职责：

* **编排器** — 协调多个智能体之间的工作。它接收任务、制定计划、将步骤拆分为问题并进行委派，然后汇总结果。运行任务必须有编排器。
* **专业智能体** — 执行特定任务，例如导入文档或发送电子邮件回复，并向编排器报告结果。

DocBits 提供可直接使用的 AI 工作团队，其中包含以下默认智能体：

* **DocBits 编排器** — 默认编排器。
* **文档处理器** — 导入并处理上传的文档。
* **电子邮件回复** — 撰写并向发件人发送回复。

这些是**系统智能体**：你可以配置其中的部分设置，但不能删除它们。你也可以创建自己的编排器和专业智能体。

### 层级结构和启用规则

运行任何任务都需要编排器，因此启用规则如下：

* **编排器**有**启用 / 禁用**开关，但只有在至少存在两个编排器时，才能**停用编排器**——系统不会允许你关闭最后一个编排器，因为那样就没有编排器来协调任务。
* 当**有多个编排器处于活动状态**时，**系统路由器**会自动启用。它负责查看每项传入任务，并将其委派给合适的编排器。如果只有一个编排器，则无需路由器，路由器会保持停用。
* **专业智能体没有启用 / 禁用开关。**你可以通过**将其分配给编排器**来控制它们可以在哪里工作（请参阅下文的_智能体池_）。未分配给任何编排器的专业智能体不可用——它仍保留在目录中，但没有编排器可以向其委派工作。因此，每个专业智能体都必须至少分配给一个编排器才能使用。

你可以在**组织架构图**中查看并调整这些关系，图中会显示“路由器 → 编排器 → 专业智能体”的结构。

### 智能体设置 <a id="agent-settings"></a>

每个智能体（系统智能体或自定义智能体）都有一个设置菜单，其中包含以下部分：

* **提示词** — 智能体的基础系统提示词。_系统智能体的提示词为只读。_
* **设置** — 智能体使用的**模型**和**推理强度**。AI 工作团队基于单一具备推理能力的模型（**DocBits Pro**）运行，因此无需调整低级参数，只需使用一个控制项——**推理强度**——来控制智能体的思考力度（进而影响费用）：
  * **无** — 速度最快、费用最低；不进行推理。
  * **低** — 适用于简单任务，进行少量推理。
  * **中** _(默认)_ — 在质量和费用之间取得平衡。
  * **高** — 适用于较难任务的深度推理；费用较高。
  * **超高** — 最大推理强度；费用最高。
* **审批模式** — 控制智能体的哪些工作需要人工在[收件箱](ai_workforce.md#inbox)中签核：
  * **无** — 智能体自动运行所有工具；无需提交审批。
  * **关键** _(默认)_ — 只有标记为 **critical** 的工具需要审批；其他工具均自动运行。关键工具是涉及敏感写入或外部操作的工具（例如_上传 / 导入文档_、_更新文档字段_、_回复电子邮件_、_发送通知_）。此模式下，关键工具**始终会在收件箱中提交审批请求**。你可以单独调整工具设置（将通常安全的工具标记为需要审批，或取消某个关键工具的标记）；这些单工具覆盖设置仅在关键模式下生效。
  * **全部** — 智能体运行的每个工具都需要审批。
*   **自定义指令** — 自由文本，用于描述智能体的工作习惯（即使是系统智能体也可以编辑）。默认模板如下：

    > **分类：**对上传的文档使用 DocBits 分类器。只有在未附加文档时，才根据电子邮件主题 / 正文进行判断。
    >
    > **字段覆盖：**无 — 按原样接受提取出的值。
    >
    > **审批：**未配置。（若要要求特定操作经过人工审批，请写明操作及触发审批的阈值。）
    >
    > **项目分配：**根据项目描述进行匹配；如果匹配结果不理想，优先不分配任务。（若要覆盖此规则，请列出关键词或发件人模式：例如 `supplier@acme.com → Acme Onboarding`。）
* **技能** — 智能体获准使用的工具（例如_上传文档_或_列出用户_）。每个工具要么标记为**关键**（涉及敏感写入或外部操作），要么标记为非关键；此标记决定上述审批行为。_系统智能体的技能不可编辑。_
* **智能体池** — _仅适用于编排器。_此处会列出可用智能体，你可以选择该编排器可以委派工作的专业智能体。专业智能体必须在此处分配给编排器（或分配给另一个编排器），才能执行工作；如果某个专业智能体未分配给任何编排器，则完全不可用。

### 创建自定义智能体

除了默认智能体之外，你还可以创建自己的**编排器**和**专业智能体**，以适应你的流程。打开**智能体 → 创建智能体**，启动向导。向导会引导你完成上述配置：选择**角色**（编排器或专业智能体），为智能体填写**名称**和清晰的**描述**（系统会根据描述选择编排器，而编排器会根据描述选择专业智能体），编写提示词，选择技能，设置推理强度；如果创建的是编排器，还要在其智能体池中选择专业智能体。你可以随时完整编辑或删除自定义智能体。
