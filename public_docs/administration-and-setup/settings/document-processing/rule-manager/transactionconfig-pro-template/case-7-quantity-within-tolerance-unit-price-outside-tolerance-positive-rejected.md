# 案例 7: 数量在容差范围内，单价超出容差（正向超差，已拒绝）

以下场景是一种说明性的已配置映射，并非经过验证的已部署默认模板。实际输出、金额、正负号和文档类型取决于生效的 `conflict_resolution` 规则与表达式、导出映射和审批决定。下文所述的任何借项通知单或贷项通知单均以该配置为条件；该示例不保证自动开具，也不保证符合法律要求。

## 场景:

数量在容差范围内，但单价超出可接受范围（正向容差）且未获批准。

## 操作:

系统拒绝发票单价，将其调整为与采购订单一致，并可能生成借项通知单以处理多收的金额。

## 示例:

* **Purchase Order (PO):**
  * Quantity: 200 件
  * Unit Price: 每件 $15.00
  * Total Amount: $3,000.00
* **Invoice Received:**
  * Quantity: 198 件——比 PO 值低 1%，在配置的 ±2% 容差范围内。
  * Unit Price: 每件 $17.00——比 PO 值高 13.33%，超出配置的 ±1% 容差；已拒绝。
  * Total Amount: $3,366.00
* **Tolerance Levels:**
  * Quantity Tolerance: ±2%
  * Unit Price Tolerance: ±1%

由于数量（198 件）在可接受的容差范围内，但单价（$17.00）超出可接受容差且未获批准，系统将:

1. **拒绝发票单价:** 系统不接受发票中的单价 $17.00。
2. **调整单价:** 系统将单价调整为与原采购订单单价一致。
   * 调整后单价 = $15.00（来自 PO）
3. **计算更正后的总金额:** 使用调整后的单价，系统重新计算总金额。
   * **Corrected Total Amount = Quantity × Adjusted Unit Price**
   * **Corrected Total Amount = 198 units × $15.00 per unit = $2,970.00**
4. **生成借项通知单:** 系统生成借项通知单以处理多收造成的差额。
   * **Debit Note Amount = Original Invoice Total - Corrected Total Amount**
   * **Debit Note Amount = $3,366.00 - $2,970.00 = $396.00**
   * 该借项通知单表示供应商多收的金额。
5. **处理发票:** 系统按更正后的总金额 $2,970.00 处理发票，并签发金额为 $396.00 的借项通知单以抵消多收的金额。

这种做法确保任何多收的金额都得到更正，使交易符合采购订单条款，并保护企业的财务利益。
