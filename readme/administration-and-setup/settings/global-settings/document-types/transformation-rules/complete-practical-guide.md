## 四个适用范围

| 范围 | 输入和目标 | 典型任务 |
| --- | --- | --- |
| 单据头字段 | 每个文档一个字段；源可以是另一个单据头字段 | 清理发票编号，复制采购订单号 |
| 表格列 | 所选表格每行的所选列 | 统一物料编号或单位代码 |
| 表格行 | 整个表格 | 删除行或添加指定明细项 |
| 路由 | 文档属性 `sub_org_id` | 分配现有子组织 |

各范围按 **单据头字段 → 路由 → 表格行 → 表格列** 的顺序执行。在单个范围内，优先级和规则键决定顺序。规则的步骤从上到下运行。因此，后续规则可以读取已更改的值。单个规则的优先级不会反转各范围的顺序。

## 编辑器的所有步骤

经验证的编辑器为单据头/列提供 14 个值步骤，为整个表格提供两个步骤，以及路由中的固定分配。`fix_value` 和固定路由分配在服务器端均使用 `set_value`。此外，接口还识别 `default`；该步骤在经验证的普通步骤菜单中不提供。

| 步骤 | 变体和参数 | 示例 | 限制和对照验证 |
| --- | --- | --- | --- |
| 更改大小写 (`case`) | upper, lower, title, capitalize | `inv-4711` → `INV-4711` | Title: `acme gmbh` → `Acme Gmbh`; capitalize: `aCME GMBH` → `Acme gmbh`。专有名词/缩写可能在业务上产生不期望的更改。对于 `capitalize`，经验证的浏览器预览保持其余部分不变，而服务器将其小写；需单独验证服务器值。 |
| 修剪 (`trim`) | 两侧 / 左侧 / 右侧；字符留空 = 空白字符 | `  4711  ` → `4711` | `47 11` 保留。左侧字符 `0`: `004711` → `4711`，但 `000` → 空。字符是一个集合，不是完整的前缀文本。 |
| 填充 (`pad`) | 最小长度，单个填充字符，左/右 | 长度 10，左侧 `0`: `4711` → `0000004711` | 已有 11 个字符保持 11 个字符。右侧 `_`，长度 6: `ABC` → `ABC___`。 |
| 截断 (`truncate`) | 最大长度 | 长度 10: `ABCDEFGHIJKL` → `ABCDEFGHIJ` | `ABC` 保持 `ABC`。截断会丢失信息，并可能导致编号合并。 |
| 词缀 (`affix`) | 添加/移除前缀/后缀 | `INV-` + `4711` → `INV-4711` | 已存在的精确词缀不会重复添加。移除仅在相应边缘生效，并注意大小写。 |
| 清理字符 (`sanitize`) | 保留字母数字 / 字母 / 数字 / 字母数字+空格；或移除字符类 | `DE 123.456.789` → `DE123456789` | 标记字符可能具有语义意义。移除时，输入为正则表达式字符类；需正确保护连字符，例如 `.\-/`。 |
| 子串 (`substring`) | 起始 + 长度 **或** 起始 + 结束；允许负索引 | 起始 3，结束 7: `DE-4711-X` → `4711` | 起始从 0 开始计数，结束为不包含。起始 −4：最后四个字符。需要独立的原始源。 |
| 提取 (`regex_extract`) | 正则表达式，捕获组 | `PO[- ]?(\d+)`，组 1: `Order PO-45001234` → `45001234` | 首个匹配；组 0 = 完整匹配。无匹配时：空。需要独立源。 |
| 查找和替换 (`regex_replace`) | 模式，替换，数量 | `\s+` → 空格: `ACME    GmbH` → `ACME GmbH` | 数量 0 = 全部，1 = 首个匹配。需要独立源。复杂模式的浏览器/服务器正则表达式需分别验证。 |
| 值映射 (`value_map`) | 完整的从→到配对；忽略大小写；无匹配时的替换 | `stk` → `PCE` 使用 `STK→PCE` 和忽略大小写 | 空替换表示 **保留输入**。`BOX` 保持 `BOX`；固定替换 `C62` 会覆盖 `BOX`。不会自动修剪。 |
| 格式化日期 (`date_format`) | 输出模式，例如 `%d.%m.%Y`, `%m/%d/%Y`, `%Y-%m-%d`, `%d %b %Y` | `2026-10-28` → `28.10.2026` 在文本目标中 | 对于 DATE 单据头字段，保存值可能保持 ISO 格式，仅显示发生变化。无法读取的文本保持不变；服务器测试会说明原因。 |
| 格式化数字 (`number_format`) | de_DE / en_US / en_GB / fr_FR；最小/最大小数位数 | `1234.5` → `1234,50` 或 `1234.50` 在经验证的服务器结果中 | 经验证的服务器结果中无千位分隔符。无货币或数量转换。需单独验证舍入和重新处理。 |
| 固定值 (`fix_value` 在编辑器中，`set_value` 在 API 中) | 单个固定值 | `USD` → `EUR` | 也会覆盖现有值。不要与默认值混淆。 |
| 清空 (`clear`) | 无参数 | `Altwert` → `""` | 清空值；不删除字段定义或文档。 |
| 删除所有行 (`clear_rows`) | 仅表格行 | 2 个明细项 → 0 | 可能使行引用和现有 PO 匹配失效。 |
| 添加行 (`add_row`) | 开头/结尾；每列固定值或单据头源 | 数量 `1`，净额来自 `header.total_net_amount` | 不预先删除时，仅适合一次性执行。不会自动聚合现有明细项。 |
| 固定子组织 (`set_value`，路由) | 子组织选择中的现有目标 | 供应商 A → 子组织 北部 | 非任意状态/用户/权限属性。或者通过 `value_map` 和源进行分配。 |

### 通过接口设置默认值

`default` 仅在输入缺失/为空时补充其值。使用默认值 `1`，`null` 和 `""` 产生值 `1`；`0` 保持 `0`，`100` 保持 `100`。这在服务器端已验证。普通编辑器在验证状态下没有为此提供独立步骤。业务上对应的简单情况通常可用 **目标为空 → 固定值** 表示。这是带有分配的规则条件，不是隐藏的菜单项。

## 条件和源

使用"始终"时，规则对文档类型无业务限制适用。"仅当…"通过条件进行限制。单据头值在上下文 `header.*` 中，文档特征在 `doc.*` 中；`row.*` 仅在列规则的行上下文中可用。嵌套的与/或组允许组合条件。各运算符适用规则条件的独立文档。

**字段复制示例：** 目标 `purchase_order`，源 `header.invoice_id`，条件 `header.purchase_order` 为空，步骤 修剪 → 大写。`  po-4711  ` 产生 `PO-4711`。已正确填充的采购订单号应保持不变。不要清空错误的源：带处理的复制不会移动源。

**物料编号示例：** 表格 `INVOICE_TABLE`，列 `ITEM_NUMBER`，移除前缀 `Art.-Nr. ` → 保留字母数字 → 大写。`Art.-Nr. ab-12/3` 产生 `AB123`。仅当目标系统恰好期望此形式时适用。

**总计行示例：** 对于明确界定的供应商，首先 `clear_rows`，然后 `add_row`；`POSITION=001`, `QUANTITY=1`, `NET_AMOUNT` 来自单据头净额。采购订单匹配对总计金额是否业务正确，由额外的 PO 配置和单独的匹配测试决定。

## 重复执行和一次性执行

规则可在多个处理运行中以及保存时再次运行。始终验证 **整个流水线**，而不仅是单个步骤的稳定性。

* `substring`、`regex_extract` 和 `regex_replace` 在经验证的服务器约定中不得读取其自身的目标值。需要独立源；`run_once` 不解除此要求。
* 补充已存在的精确词缀是稳定的。相反，移除多次存在的前缀可能在每次运行时继续移除。
* 同一值映射中的 `A→B` 和 `B→C` 在两次运行后可能将 `A` 最终变为 `C`。将输出再次作为输入进行测试。
* `clear_rows → add_row` 有限地重建表格。`add_row` 不预先删除时需要适当的一次性执行，否则每次保存时表格都会增长。
* "每文档仅一次"标记实际应用的规则。未满足的条件不消耗应用次数。没有可靠可读的文档/应用证明时，一次性规则的执行会被暂缓。

## 查找之后和采购订单匹配之前

"也在主数据搜索后执行"在查找填充之后和 PO 匹配之前添加一个阶段。仅相应标记的规则在此附加阶段运行。其余运行保持不变。与一次性执行结合时，规则在首次提取运行中等待后续阶段；如果查找阶段缺失，则考虑后续常规运行。当前编辑器的阶段显示展示这些差异。

## 可靠的验收测试

1. 确定业务目标、目标系统格式和适用范围。
2. 准备合适的原始值、反例、空值和已处理结果。
3. 在预览中验证条件和所有中间值。
4. 对相同示例执行服务器端测试；特别比较复杂模式和数字/日期格式。
5. 保存并重新打开规则。仅在预定测试范围内使用活动规则。
6. 对隔离文档保存、重新加载并验证值和显示；对表格还需验证行数和列值。
7. 再次保存。结果不得被意外进一步更改或倍增。
8. 如业务需要，额外验证 PO 匹配和目标系统中的实际接收。单独的转换日志不能证明这些结果。

## 转换不会自动完成的事项

无新的 OCR 识别、无数学单位或货币转换、无任意表格聚合、无完整 ERP 过账。路由仅限于提供的文档属性。可用性和精确显示取决于所使用的版本、文档类型和组织配置。
