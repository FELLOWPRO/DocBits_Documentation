# V1: Infor Ming.le Portal SSO

This guide is for **Infor Ming.le Portal V1** with LN or an older M3 interface. If your tenant uses a newer Infor OS Portal, ask your Infor administrator which federation procedure applies before using these steps. You need administrator access to both your Infor tenant and your DocBits organisation. Keep an existing administrator sign-in available until a test user can sign in through SSO.

## 1. Get the DocBits service provider values

Sign in to the correct DocBits environment and organisation. Open **Settings → Integration & SSO → SSO Service Provider Settings**. Copy the **Entity ID**, **SSO Url** and **SLO Url** using the buttons next to each value. Use **Download Certificate** if Infor requires the DocBits signing certificate. **Download Metadata** exports DocBits *service provider* metadata. The Sandbox URLs in this example are specific to the test organisation; do not copy them into another tenant.

![Current DocBits SSO Service Provider Settings in the English Sandbox test organisation, showing Entity ID, SSO Url, SLO Url, and download buttons.](../../../../../../.gitbook/assets/dbdc-192-infor-v1-sso-settings-en.png)

## 2. Register DocBits in Infor

In your **Infor Ming.le Portal V1** tenant, open **User Management → Security Administration → Service Provider**, then add a SAML service provider for DocBits. Your Infor administrator should confirm that this is the correct screen and application type for your tenant. Map the values as follows:

| Infor service provider field | Value from DocBits |
| --- | --- |
| Entity ID | Entity ID |
| SSO Endpoint | SSO Url (assertion consumer endpoint) |
| SLO Endpoint | SLO Url (logout endpoint) |
| Signing Certificate | Certificate from Download Certificate, if required |
| Name ID Format / Mapping | Email address, after confirming the Infor user identifier matches the DocBits user |

**Do not paste the SLO Url into SSO Endpoint.** These are different endpoints. Save the service provider. Infor's [service provider configuration guide](https://docs.infor.com/inforos/2026.09/en-us/useradminlib_cloud/minceag_cloud_osm/vxs1562872848076.html) describes the field roles and the **Export SAML Metadata** action. Infor menus and permissions can differ by tenant and release.

## 3. Import the Infor identity provider metadata into DocBits

In Infor, open the saved DocBits service provider, choose **View** for **Identity Provider Information**, and **Export SAML Metadata**. This file contains the *Infor identity provider* details. It is different from the DocBits service provider metadata downloaded in step 1.

In DocBits, return to **Settings → Integration & SSO → Identity Service Provider Settings**. Enter the Infor **Tenant ID**, choose the Infor metadata XML under **Upload file**, then select **Configure**. Confirm the tenant ID and XML with your Infor administrator before saving; the Sandbox screenshot does not represent your production tenant.

## 4. Check sign-in

Assign an appropriate Infor user to the DocBits application in Ming.le and test sign-in with that user. Check that the user's email identifier matches a DocBits user. Keep the original admin session open while you test. If login or logout fails, compare the service provider endpoints, Infor metadata, certificate and Name ID mapping with both administrators.

**Verification scope:** The DocBits screen and navigation above were checked in the English Sandbox test organisation. No Infor tenant was available for this update, so the Infor screens, metadata exchange and live sign-in were not tested. The previous Infor screenshots were removed because their current state could not be verified; use the linked Infor documentation and your tenant's administrator for its live interface.
