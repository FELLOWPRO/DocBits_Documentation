# V2: SSO w Infor OS Portal

Skorzystaj z tego przewodnika, jeśli Twoja organizacja uruchamia DocBits z **Infor OS Portal V2**. Wymagany jest administrator zarówno Infor, jak i DocBits. Podczas testowania SSO zachowaj otwartą dotychczasową sesję administratora DocBits. Menu i nazwy pól Infor zależą od wydania tenanta; potwierdź je u administratora Infor.

## 1. Pobierz wartości SAML DocBits

W odpowiedniej organizacji DocBits otwórz **Settings → Integration & SSO → SSO Service Provider Settings**. Skopiuj **Entity ID**, **SSO Url** i **SLO Url**. Użyj **Download Certificate**, jeśli formularz dostawcy usług Infor wymaga certyfikatu podpisującego. **Download Metadata** to plik XML *dostawcy usług* DocBits; nie jest to plik metadanych dostawcy tożsamości Infor używany w kroku 3. Adresy URL na obrazie Sandbox należą wyłącznie do tej organizacji testowej.

![Aktualny ekran Integration & SSO w DocBits w angielskiej organizacji testowej Sandbox, z Entity ID dostawcy usług, SSO Url, SLO Url oraz pobieraniem certyfikatu i metadanych.](../../../../../../.gitbook/assets/dbdc-182-infor-v2-sso-settings-en.png)

## 2. Dodaj DocBits jako dostawcę usług w Infor

W Infor OS Portal otwórz **OS → Security → Security Administration → Service Provider**, jeśli taka jest ścieżka w Twoim tenancie. Dodaj dostawcę usług SAML i zastosuj następujące mapowanie:

| Pole Infor | Wartość DocBits |
| --- | --- |
| Entity ID | Entity ID |
| SSO Endpoint | SSO Url, punkt końcowy konsumenta asercji |
| SLO Endpoint | SLO Url, punkt końcowy wylogowania |
| Signing Certificate | Download Certificate, jeśli jest wymagany |
| Name ID Format / Mapping | Adres e-mail, po sprawdzeniu, że odpowiada użytkownikowi DocBits |

Poprzedni przewodnik nakazywał wpisać **SLO Url** w polu **SSO Endpoint**. To błąd: każdy adres URL należy wpisać w odpowiadające mu pole. Zapisz dostawcę usług. [Przewodnik po dostawcy usług](https://docs.infor.com/inforos/latest/en-us/useradminlib_cloud/inforos_security/jho1449385888462.html) Infor wyjaśnia nawigację i wymaganą rolę; jego [przewodnik po polach SAML](https://docs.infor.com/inforos/2026.09/en-us/useradminlib_cloud/mineeag/min1772650388038.html) wyjaśnia role punktów końcowych.

## 3. Zaimportuj metadane dostawcy tożsamości Infor

Otwórz zapisanego dostawcę usług w Infor i wybierz **View → Export SAML Metadata** dla dostawcy tożsamości Infor. Wróć do DocBits i otwórz **Settings → Integration & SSO → Identity Service Provider Settings**. Wprowadź **Tenant ID** Infor, wybierz plik XML Infor w polu **Upload file**, a następnie kliknij **Configure**. Potwierdź identyfikator tenanta i metadane u administratora Infor. Nie wgrywaj tutaj pliku XML dostawcy usług DocBits z kroku 1.

## 4. Dodaj kafelek DocBits w Infor OS Portal

W Infor OS Portal otwórz **Portal → Applications → Add Application**. Zarejestruj DocBits jako aplikację spoza Infor dla swojego tenanta, podaj nazwę wyświetlaną, ikonę i unikalny Logical ID oraz ustaw **adres URL aplikacji** na swój zwykły adres logowania lub uruchamiania DocBits. Adres URL aplikacji w portalu otwiera interfejs użytkownika; **nie** jest to punkt końcowy SAML SSO/ACS z kroku 2. Skorzystaj z [przewodnika po aplikacjach spoza Infor](https://docs.infor.com/inforos/latest/en-us/useradminlib_cloud/inforospag/lsm1436532874794.html), aby poznać aktualny formularz, opcje nawigacji i uprawnienia. Nadaj użytkownikowi testowemu dostęp do aplikacji w portalu.

## 5. Zweryfikuj na jednym użytkowniku

Wyloguj się w osobnej sesji przeglądarki, otwórz kafelek DocBits z Infor i potwierdź, że adres e-mail przypisanego użytkownika wskazuje właściwe konto i organizację DocBits. Sprawdź również wylogowanie. Jeśli któreś z nich nie działa, porównaj z obydwoma administratorami metadane Infor, adresy SSO/SLO, certyfikat, Name ID i adres URL kafelka w portalu. Zachowaj pierwotną sesję administratora do zakończenia testu.

**Zakres weryfikacji:** Powyższy ekran DocBits został przechwycony w angielskiej organizacji testowej Sandbox. Nie był dostępny żaden tenant Infor, dlatego menu portalu Infor, import metadanych, tworzenie kafelka i rzeczywiste SSO nie były testowane na potrzeby tej aktualizacji. Stare, hostowane zewnętrznie obrazy Infor, w tym prywatne załączniki poczty, zostały usunięte; skorzystaj z podlinkowanej dokumentacji Infor i administratora swojego tenanta, aby poznać ten interfejs.
