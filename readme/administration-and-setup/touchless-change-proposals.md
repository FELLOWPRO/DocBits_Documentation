# 无接触智能：变更提案和报告


建议可以附带一个**变更提案**，即一项有助于改善结果的设置变更。管理员分四步处理：

1. **预览**：显示变更内容（当前值 → 建议值）以及 DocBits 的预期效果。不会保存任何内容。只有查看预览后才能**应用**。
2. **应用**：准确保存预览中的变更。该操作会记录在日志中。
3. **衡量**：DocBits 会比较同一文档类型在**变更前后**、时长相同的两个时段内的无接触率。每个时段至少需要 **20 份文档**，否则结果会显示为*无法衡量*。
4. **撤销**：恢复变更前的设置。

{% hint style="warning" %}
变更前后的差异是**观察结果**，不能证明因果关系。同期可能还有其他变化（例如新增供应商或季节性高峰）。
{% endhint %}

**示例。**你为发票应用了*启用自动 PO 匹配和导出*。两周后，**变更历史记录**显示：变更前纯处理率为 52 %（210 份文档），变更后为 61 %（198 份文档）。提升了 9 个百分点，且文档数量足够，因此可以衡量。


管理员还会在关键指标和图表之间看到两个版块：

* **改进请求**：用户通过验证助手提交的建议，分为 **未处理** 和 **历史记录** 两个标签页。
* **已学习的规则提案**：DocBits 根据团队的更正结果学习到的规则，例如“对于供应商 X，请替换字段 Y 中的值”。创建规则前，请检查它会替换团队已接受值的那些文档。**激活后**版块会显示规则生效前后目标字段的手动更正情况。


<figure><img src="../.gitbook/assets/touchless-consulting-report.png" alt="咨询报告，包含排名前三的提案、排名表以及按领域划分的问题"><figcaption><p>咨询报告：排名靠前的提案、按阻碍因素排列的清单（含文档数量和每月预估影响），以及按领域划分的问题。示例组织使用演示数据；供应商名称均为虚构。</p></figcaption></figure>

管理员可以在标签页底部找到**咨询报告**。点击**创建报告**即可加载报告。报告会汇总本组织的以下信息：

* **影响最大的变更**，按影响排名；每项包含领域、问题、建议操作、文档数量以及每月**预估**影响，
* **每个问题所属的领域**（提取、主数据、PO 匹配、自动记账、设置、流程），
* **表格配置检查**，例如按文档类型和列检查*未使用结构化表格输出*或*表格列类型不匹配*。

影响数值均为**估算值**。如果报告显示*禁止访问*，则说明你的角色没有权限。
