# 已分配组条件

**用途：**

此工作流卡片会根据任务或文档是否分配给特定组或多个组来执行操作。它使用条件逻辑，根据组分配情况触发或阻止特定操作，适用于需要按组进行处理的工作流。

**卡片组件：**

1. **运算符**
   * **说明：** 定义要应用于组分配的逻辑条件。
   * **选项：**
     * **IS（是）：** 如果文档或任务的已分配组与指定列表中的任一组匹配，则触发操作。
     * **不是（不是）：** 如果文档或任务的已分配组与指定列表中的任何组都不匹配，则触发操作。
2. **组列表**
   * **说明：** 用于与已分配组进行比较的组列表或选择项。
   * **详情：** 此列表可包含一个或多个组，因此该卡片能够有效处理单组和多组条件。

**功能：**

* **识别组分配：** 自动识别系统中分配给特定任务或文档的一个或多个组。
* **条件评估：**
  * 使用 **IS（是）** 运算符时，卡片会检查已分配组是否属于“组列表”中的任一组。
  * 使用 **不是（不是）** 运算符时，卡片会确保已分配组不属于列表中的任何组。
* **执行操作：**
  * **条件为真：** 如果组分配符合条件（**IS（是）** 或 **不是（不是）**），则触发相关操作，例如发送通知、启动任务、发起审批或执行其他工作流步骤。
  * **条件为假：** 如果条件不满足，工作流将不会继续。

**用户交互：**

* **设置和配置：**&#x55;用户通过选择运算符并在“组列表”中指定相关组来配置此卡片。设置应简单直观，以便从可能很大的组库中进行选择。
* **监控和报告：**\
  系统应提供监控和报告此卡片所触发操作的功能，以便了解分配准确性和流程效率。
* **错误处理和通知：**\
  用户应能选择在分配出现问题时接收提醒或通知，例如任务未分配或组选择出错。

**结论：**\
“已分配组条件”工作流卡片对于管理依赖组分配的文档和任务工作流至关重要。通过根据任务或文档是否分配给特定组来设置条件，它可确保只有适当的组交互才会触发工作流，从而提升团队间的责任落实和任务管理。

## 实际例子

**何时使用：** 对两个审核团队应用相同的规则。

**配置：** 选择 is-one-of 和配置的组 `Demo Finance` 和 `Demo Procurement`。

**预期结果和反例：**分配给任一选定组的文档通过。仅分配给`Demo Support`的文档失败。

这是说明性配置和预期结果。使用测试组织中配置的字段、用户和组；这并不是说这个例子已经被执行了。
