**用途**

此工作流卡片根据任务或文档是否分配给特定用户或一组用户来管理操作的执行。它采用条件逻辑来触发或阻止特定操作，非常适合需要按用户进行处理的工作流。

**卡片组件**

1. **运算符**
   * **说明**：定义要应用于用户分配情况的逻辑条件。
   * **选项**：
     * **IS**：如果文档或任务的指定用户与列表中的任意用户匹配，则触发操作。
     * **不是**：如果文档或任务的指定用户与列表中的任意用户都不匹配，则触发操作。
2. **用户列表**
   * **说明**：用于与指定用户进行比较的用户列表或选择项。
   * **详情**：此列表可以包含一个或多个用户，使卡片能够有效处理单用户和多用户条件。用户可以通过复选框、多选下拉菜单或类似的界面元素进行选择。

**功能**

* **识别用户分配情况**：自动识别 ERP 系统中特定任务或文档的指定用户。
* **条件评估**：
  * 使用 **IS** 运算符时，卡片会检查指定用户是否在用户列表中。
  * 使用 **不是** 运算符时，卡片会确保指定用户不在用户列表中。
* **执行操作**：
  * **条件为真**：如果用户分配情况满足条件（IS 或 IS NOT），则触发相关操作，例如发送通知、发起任务、进行审批或执行其他工作流步骤。
  * **条件为假**：如果条件不满足，工作流将不会继续。

**用户交互**

* **设置与配置**：用户通过选择运算符并在用户列表中指定相关用户来配置卡片。设置应当简单直观，以便从可能规模较大的用户群体中进行选择。
* **监控与报告**：ERP 系统应提供监控和报告此卡片所触发操作的功能，以便了解分配准确性和流程效率。
* **错误处理与通知**：如果分配出现问题（例如任务未分配或用户选择有误），用户应能选择接收提醒或通知。

#### 结论

“指定用户条件”工作流卡片是管理依赖用户分配的文档和任务工作流的重要工具。通过允许根据任务或文档是否分配给特定用户来设置条件，它可以确保只有适当的用户交互才会触发工作流，从而增强团队内的责任落实和任务匹配度。清晰记录此卡片的信息有助于用户了解其重要性，并将其有效整合到工作流中，确保根据用户角色和职责顺畅、高效地执行操作。

## 实际例子

**何时使用：** 仅当将文档分配给经批准的审阅者时才继续。

**配置：** 选择 is-one-of 以及配置的演示用户`Demo Reviewer A` 和 `Demo Reviewer B`。

**预期结果及反例：**分配给`Demo Reviewer B`的文档通过；分配给不同用户的失败。

这是说明性配置和预期结果。使用测试组织中配置的字段、用户和组；这并不是说这个例子已经被执行了。
