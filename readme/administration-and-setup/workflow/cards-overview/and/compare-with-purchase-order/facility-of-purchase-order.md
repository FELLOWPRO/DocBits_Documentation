# 采购订单的设施

<figure><img src="../../../../../.gitbook/assets/workflow_card_condition_check_facility_in_po_v2-zh-cn.png" alt="采购订单的设施, 版本 2" width="634"><figcaption><p>版本 2</p></figcaption></figure>

## 用途：

此工作流卡片会将与文档匹配的采购订单的设施与一组设施代码进行核对。它可以根据订单所属的设施（地点）以不同方式处理文档，例如将文档路由给负责该设施的团队。

此卡片运行前应先完成采购订单匹配。如果没有匹配的采购订单，卡片会报告缺少数据。

## 卡片组件：

1. **任意/全部**
   * **描述：** 如何将匹配的采购订单的设施代码与列表进行比对。
   * **选项：**
     * **任何：** 列表中至少有一个条目出现在匹配的采购订单的设施代码中。
     * **全部：** 匹配的采购订单的每个设施代码都在列表中。如果未设置值，卡片会使用 **全部**。
2. **操作员**
   * **描述：** 设施应在列表中还是不在列表中。
   * **选项：**
     * **是**
     * **不是**
3. **设施名称代码**
   * **描述：** 与采购订单设施进行比较的设施代码。
   * **详细信息：** 可以输入多个代码，以逗号分隔。

## 功能：

* **条件评估：** 卡片读取与文档匹配的采购订单号，加载这些采购订单，并收集每个采购订单的设施（地点）。没有设施的采购订单会被跳过。随后，收集到的设施代码会与卡片上的 **设施名称代码** 进行比较。
  * 使用 **任何** 和 **是** 时，比较不区分大小写，并且当列表中的条目是较长设施代码的一部分时也算匹配（例如，条目 `WH` 可以在 `WH01` 中找到）。
  * 使用 **全部** 和 **是** 时，采购订单的每个设施代码都应以完全相同的拼写（包括大小写）出现在列表中。
  * 如果匹配的采购订单都没有设施，则 **全部** 满足条件，**任何** 不满足条件。
  * 使用 **不是** 时，结果并不只是 **是** 的反面。卡片日志会显示找到了哪些代码以及哪些代码未匹配，有助于检查特定设置下的行为。
* **执行操作：**
  * **条件为真：**\
    如果条件满足，工作流继续，例如执行仅适用于所列设施的步骤。
  * **条件为假：**\
    如果条件不满足，工作流会因条件未满足而停止。
* **缺少数据：** 如果卡片上未输入任何设施代码，或文档没有匹配的采购订单，卡片不会评估条件，并会在工作流日志中报告缺少的数据。

## 设置和配置：

* 可以在采购订单匹配之后，从 **与采购订单比较** 类别中添加此卡片作为 And 条件，然后设置 **任何** 或 **全部**、运算符以及以逗号分隔的设施代码。按照采购订单上的拼写输入代码是最稳妥的做法，因为 **全部** 会按完全一致进行比较。
* 可以在 Workflow Builder 的卡片菜单中使用 **测试卡片**，在现有文档上试用配置。卡片日志会列出匹配的采购订单、在其上找到的设施代码以及未匹配的代码。

## 结论：

“采购订单的设施”工作流卡片将所订购货物的设施用作工作流条件。这样，一个工作流就能基于采购订单数据，而非文档上打印的内容，对不同设施的文档进行不同处理。
