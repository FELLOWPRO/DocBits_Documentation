## 目的

该卡允许您将数据发送到外部网站或服务并接收返回的信息。可以将其想象为向外部服务发送问题并获得可在工作流程中使用的答案。

**真实示例：** 您的公司使用另一个网站上的定价系统。该卡可以自动向定价系统询问商品的当前价格，并将该价格带入您的文档中。

***

## 何时使用此卡

当您需要时使用此卡：

* 从外部服务获取信息（例如定价、验证或查找数据）
* 将文档信息发送到另一个系统进行处理
* 与第三方服务集成
* 自动获取数据，无需手动查找
* 将多个业务系统连接在一起

**常见场景：**

* 从数据库查找供应商信息
* 从定价服务获取实时定价
* 针对外部系统验证数据
* 从物流提供商获取运输信息

***

## 它是如何运作的

1. **条件检查**：工作流程首先检查“Where”和“And”部分中的条件是否满足
2. **准备数据**：卡片收集您配置的参数
3. **发送请求**：它将您的数据发送到外部API/服务
4. **接收响应**：外部服务响应数据
5. **Continue**：工作流程在后续卡片中使用此数据

***

## 参数解释

### API 端点 URL

**它是什么：**你想要通信的外部服务的地址

**示例：** `https://api.supplier-system.com/product/pricing`

**如何找到它：** 向您的 IT 团队或服务提供商询问他们的 API 端点

***

### HTTP方法

**它是什么：**要发送的请求类型

**选项：**

* **GET**：请求信息（如提问）
* **POST**：发送新数据
* **PUT**：更新现有数据
* **DELETE**：删除数据

**最常见：** GET（用于获取信息）

***

### 标头

**它是什么：**您所调用的服务的其他说明

**示例：**

```
Authorization: Bearer your-api-key
Content-Type: application/json
```

**为什么需要：** 服务通常需要身份验证或特定格式指令

***

### 参数（查询参数）

**它是什么：** URL中传递的额外信息

**示例：**

```
?supplier_id=12345&currency=USD
```

**真实示例：** 如果您询问价格，参数可能包括供应商 ID 和货币

***

### 请求数据（正文）

**它是什么：**您发送到服务的信息

**示例：**

```json
{
  "product_id": "ABC123",
  "quantity": 100,
  "currency": "EUR"
}
```

**使用时：**使用POST或PUT方法时

***

## 分步示例

### 场景：获取实时供应商定价

**设置：**

1. **卡片类型：** 调用API
2. **API端点：**`https://api.suppliers.com/v1/prices`
3. **方法：** POST
4. **标题：**`Authorization: Bearer YOUR-API-KEY`
5.  **请求数据：**

    ```json
    {
      "product_id": "ABC123",
      "quantity": 100
    }
    ```

**发生了什么：**

1. 文件到达时产品 ID：ABC123，数量：100
2. 卡向供应商的API发送请求
3. 供应商的 API 响应：`{"unit_price": 25.50, "total_price": 2550}`
4. 工作流程继续处理此定价信息
5. 下一张卡可以使用此数据来验证发票价格

## 配置步骤

### 1. 获取API信息

联系外部服务提供商并请求：

* [ ] API 端点 URL
* [ ] 身份验证方法（API 密钥、用户名/密码、OAuth）
* [ ] 必需参数
* [ ] 预期响应格式
* [ ] 速率限制或配额

### 2. 配置卡

1. 输入 API 端点 URL
2. 选择 HTTP 方法（通常是 GET 或 POST）
3. 如果需要，添加身份验证标头
4. 添加任何必需的参数
5. 如果需要，将请求数据格式化为 JSON

### 3. 测试卡

1. 使用测试文档
2. 运行工作流程
3. 检查是否正确收到响应
4. 验证数据格式是否符合预期

***

## 常见的响应场景

### 成功响应（状态代码 200）

```json
{
  "success": true,
  "data": {
    "price": 150,
    "currency": "EUR",
    "delivery_days": 5
  }
}
```

✅ 数据可供下一张卡使用

### 错误响应（状态代码 404）

```json
{
  "error": "Product not found"
}
```

⚠️ API 找不到您要查找的内容

### 超时

外部服务在时限内没有响应⚠️检查服务是否可用或者端点URL是否正确

## 示例工作流程

### 示例 1：自动价格验证

**场景：** 根据供应商的当前定价验证发票价格

**流量：**

1. 文件随发票行项目一起到达（产品：A123，价格：50 欧元）
2. **调用API卡**→询问供应商API：“A123当前价格是多少？”
3. 供应商回应：“48 欧元”
4. **条件卡** → 检查发票价格（50 欧元）是否在当前价格（48 欧元）的 5% 以内
5. **批准卡** → 如果在公差范围内则批准

### 示例 2：自动供应商查找

**场景：**从中央数据库获取供应商主数据

**流量：**

1. 发票附有供应商代码：SUPP-789
2. **调用API卡**→询问系统：“给我供应商SUPP-789的详细信息”
3. 系统响应：姓名、联系方式、条款等。
4. **设置字段卡** → 使用此数据填充文档字段
5. **导出卡** → 导出信息齐全

### 示例 3：实时运费

**场景：** 根据目的地自动获取运费

**流量：**

1. 文件有送货地址
2. **调用API卡**→询问运输商：“到\[地址]的费用是多少？”
3. 供应商回复运费
4. **计算卡** → 将运费添加到发票总金额中
5. **导出卡** → 发送更新后的总计

## 故障排除

### “连接超时”错误

**原因：** API服务无响应

**解决方案：**

* [ ] 检查服务是否可用（访问网站）
* [ ] 验证端点 URL 是否正确（无拼写错误）
* [ ] 检查互联网连接
* [ ] 联系服务提供商
* [ ] 检查服务是否有速率限制（您发送的请求过多）

### “未经授权”或“403 禁止”错误

**原因：**认证失败

**解决方案：**

* [ ] 验证您的 API 密钥是否正确
* [ ] 检查您的 API 密钥是否已过期
* [ ] 确保身份验证标头格式正确
* [ ] 验证您是否具有此端点的权限

### “错误请求”或“400 错误”

**原因：**请求数据格式不正确

**解决方案：**

* [ ] 检查 JSON 语法（缺少逗号、引号等）
* [ ] 验证是否包含所有必填字段
* [ ] 检查参数名称是否与服务期望的相符
* [ ] 查阅API文档

### “响应未按预期工作”

**解决方案：**

* [ ] 使用 Postman 等工具测试 API
* [ ] 将实际响应格式与预期格式进行比较
* [ ] 检查API的文档是否更改
* [ ] 验证您发送的数据是否正确

## 安全说明

⚠️ **重要提示：** 切勿将敏感信息放入其他用户可能看到的卡配置中

* 不要对密码进行硬编码
* 安全地使用 API 密钥
* 不要在日志中包含个人数据
* 使用 HTTPS 端点（不是 HTTP）

***

## 提示和最佳实践

✅ **做：**

* 首先使用一小部分文档样本进行测试
* 保持 API 调用简单且集中
* 使用条件卡添加错误处理
* 监控 API 使用/成本
* 记录您团队的 API 要求

❌**不要：**

* 如果可以缓存数据，请为每个请求调用 API
* 忽略响应错误代码
* 在生产中使用测试 API
* 忘记添加身份验证标头
* 假设 API 始终可用

## 相关卡牌

* **ACTION\_HTTPS\_REQUEST** - 类似但更简单的 HTTPS 请求
* **CONDITION\_HTTPS\_REQUEST\_STATUS** - 检查API调用是否成功
* **ACTION\_SEND\_EMAIL** - 通过电子邮件而不是 API 发送数据
* **CALL\_API**（不同版本）-替代API调用方法
