已保存工作流程中的卡保留其卡 ID 和版本。较新的模板可以添加字段或更改行为，而无需更改之前保存的每个工作流程。在应用新版本的说明之前，请检查实际卡上的版本。

## 更改已保存的卡之前

1. 在代表性测试数据上记录其字段和当前结果。
2. 将其版本与参考版本进行比较，包括默认值和缺失数据行为。
3. 仅通过支持的构建器操作升级或更换卡，并再次检查其设置。
4. 在激活更改的工作流程之前，验证图形并测试通过、失败和丢失数据的情况。

不要仅仅为了纠正拼写而编辑存储的技术卡类型。现有工作流程可以依赖于该标识符。不受支持的版本是执行错误，而不是错误的业务条件。

## 如果没有记录卡

与管理员一起检查所选的“时间”、“然后”或“然后”组、类别、标准与高级构建器、启用的模块、权限和部署的版本。技术集成或较新的参考中提到的卡不一定适合您的组织。不要创建或导入猜测的卡定义来解决丢失的模板。

某些开发材料中描述的附加日历条件并不是每个版本中确认的可选集。文档变量设置器也是在没有通用 UI 模板的情况下实现的。使用您环境中实际可用的卡，并在依赖不可用的卡之前请求澄清。

## 取决于版本的参考

- [导出卡](export-cards-guide.md)：结果状态以及立即导出与排队导出。
- 【PO比较卡](po-comparison-versions-guide.md)：比较方向和公差基准。
- [报价比较卡](quote-comparison-guide.md)：任何/全部且缺少可比价格。
- [逻辑卡](logic-cards-guide.md)：标签、组织变量和输入类型。

使用[工作流程日志](../workflow-logs.md)来区分成功、错误条件、丢失数据、设置错误和跳过的卡。记录文档状态和卡片设置以及测试结果；仅凭卡片选择器的屏幕截图并不能建立运行时行为。

## 当前界面标签的含义

本次核对发现，部分界面标签存在语境翻译错误。请按控件的实际用途理解：

| 界面中显示的文字 | 在工作流卡片中的含义 |
| --- | --- |
| 操作员 | 比较运算符，例如相等、大于或小于；不是人员角色。 |
| 桌子 | 数据表格。 |
| 采购订单列控件中的“柱子” | 数据列。 |
| 设施筛选中的“设备名称代码” | 设施或地点的名称代码。 |
| 价值 | 字段值或数值；日期容差中的数量应理解为天数。 |
| 受让人 | 文档或任务的分配对象，例如用户或组。 |
| 决策表中的“退货” | 决策表返回的值或结果；不是商品退货。 |
| 地位 | 文档状态或工作流状态。 |
| 出口 | 向目标系统导出数据。 |
| 优先事项 | 任务或分配的优先级。 |
| HTTPS 卡片中的“标题” | HTTP 请求头；任务卡片中的“标题”仍表示任务标题。 |
