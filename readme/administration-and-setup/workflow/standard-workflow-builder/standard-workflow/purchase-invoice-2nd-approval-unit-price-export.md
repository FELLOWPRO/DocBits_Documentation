# 采购发票 - 第二次审批单价导出

<figure><img src="../../../../.gitbook/assets/Bildschirmfoto 2024-05-03 um 14.59.02.png" alt="工作流，Document type 为 Invoice，状态为 Pending Second Approval，子类型为 Purchase Invoice，包含单价比较和 Start Export"><figcaption></figcaption></figure>

此标题表示，该规则用于管理采购发票的第二阶段审批，重点关注单价，确保其符合约定条款。

#### 规则配置：

1. **当……**
   * **文档类型为发票**：此条件确保规则仅对标识为发票的文档触发，这对于准确指引工作流至关重要。
2. **并且……**
   * **文档状态为待第二次审批**：此条件表示发票正在等待第二次审批。此阶段通常会增加一道检查，确保交易最终确认前的准确性。
   * **文档字段“发票子类型”等于“采购发票”**：此条件进一步限定，规则仅适用于归类为“采购发票”的发票，以区别于其他类型的发票。
   * **逻辑单元：订单确认中的单价等于采购订单中的单价**：此条件检查订单确认中列出的单价是否与采购订单中的单价一致。只有价格一致时，发票处理才会继续，这对预算管理和财务报告至关重要。

#### 操作（然后……）：

* **开始导出**：发票满足指定条件后（即订单确认与采购订单中的单价一致），系统会触发“开始导出”操作。这通常会将发票数据导出以供进一步处理，例如发送到其他财务系统或用于报告。

#### 此规则的目的：

* **确保准确性和一致性**：通过验证订单确认与采购订单中的单价是否一致，系统有助于保持财务数据准确，并防止多收或少收款项。
* **简化财务处理**：确认价格后自动导出数据，可减少人工操作并加快财务处理周期。
* **加强合规与监督**：要求对价格进行第二次审批，增加了一层监督，这对于遵守财务政策和控制要求至关重要。

此规则展示了如何有效利用工作流自动化，在组织内精确、高效地处理财务文档，尤其适用于需要细致验证的大量交易。
